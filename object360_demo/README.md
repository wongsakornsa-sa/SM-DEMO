# Object 360 Studio — คู่มือเปิดโปรแกรมและอ่านผล

คู่มือเวอร์ชันล่าสุด อัปเดต 26 ตุลาคม 2569

โปรแกรม Demo นี้รับภาพจากกล้องหรือไฟล์วิดีโอ แล้วให้ผู้ทดลอง **หันกล้องด้วยมือและถ่ายภาพ 8 มุม** รอบจุดที่ตั้งกล้อง โดยกะระยะห่างประมาณมุมละ 45 องศา โปรแกรมใช้ YOLO ตรวจจับ **ขวด (bottle), แก้ว (cup) และเก้าอี้ (chair)** และใช้ Deep SORT กำหนดหมายเลขติดตามวัตถุ (Object ID) ไม่ตรวจจับบุคคล

โปรแกรมเปรียบเทียบการทำงานสองวิธีด้วย **ภาพ 8 ภาพชุดเดียวกัน**:

1. **วิธีที่ 1 — ประมวลผลทีละภาพ:** ถ่ายหนึ่งมุมแล้วแสดงผลตรวจจับทันที ก่อนหันไปมุมถัดไป
2. **วิธีที่ 2 — ประมวลผลหลังถ่ายครบ:** หลังถ่ายครบ 8 มุม โปรแกรมนำภาพที่บันทึกไว้กลับมาประมวลผลต่อเนื่องอีกครั้ง

## เปิดโปรแกรม

1. เปิดโฟลเดอร์ `dist\Object360Studio`
2. ดับเบิลคลิก `Object360Studio.exe`
3. รอหน้าต่าง **Object 360 Studio** ปรากฏ ไม่ต้องติดตั้ง Python หรือพิมพ์คำสั่ง
4. หากแผงตั้งค่ากล้องหรือปุ่มด้านขวามีส่วนที่อยู่ล่างจอ ให้วางเมาส์เหนือแผงนั้นแล้วเลื่อนล้อเมาส์ หรือใช้แถบเลื่อน ปรับขนาดหรือขยายหน้าต่างได้ตามพื้นที่จอ

**ถ้าจะย้ายไปเครื่องอื่น ให้คัดลอกทั้งโฟลเดอร์ `Object360Studio`** เพราะไฟล์ `_internal` ภายในเป็นส่วนที่โปรแกรมต้องใช้ เปิดเฉพาะไฟล์ `.exe` ที่แยกออกจากโฟลเดอร์นี้ไม่ได้ โมเดลเริ่มต้น `yolo11n.pt` รวมอยู่ในโปรแกรมแล้ว

## เตรียมกล้องและพื้นที่ทดลอง

วางกล้องที่จุดเดิม จัดแสงให้เห็นวัตถุชัด และวางขวด แก้ว หรือเก้าอี้ในพื้นที่ที่จะถ่าย เมื่อถ่ายแต่ละมุมให้หันกล้องด้วยมือและรอภาพนิ่งก่อนกดปุ่ม โปรแกรม **ไม่ได้สั่งให้กล้องหมุนเอง** และไม่ได้วัดองศาจริง

ในกรอบ **ตั้งค่ากล้อง** เลือกชนิดแหล่งภาพให้ตรงกับอุปกรณ์:

| ชนิดแหล่งภาพ | สิ่งที่ใส่ในช่อง “หมายเลขกล้อง / URL / พาธไฟล์” |
| --- | --- |
| **USB / virtual camera** | หมายเลขกล้อง เช่น `0`, `1` หรือ `2` กล้องจาก Camo หรือแอปอื่นใช้ได้เมื่อปรากฏเป็นกล้องเสมือนใน Windows |
| **Network stream** | URL สตรีมที่กล้องให้มา เช่น RTSP หรือ HTTP ที่ OpenCV อ่านได้ |
| **HTTP snapshot** | URL ที่ส่งภาพนิ่ง JPEG เมื่อเรียกใช้งาน |
| **Video file** | พาธไฟล์วิดีโอ หรือกด **เลือกวิดีโอ** เพื่อเลือกไฟล์ |

ค่าปกติคือกล้อง USB/กล้องเสมือนหมายเลข `0` หากไม่ทราบหมายเลขให้กด **ค้นหากล้อง** โปรแกรมจะลองหมายเลข 0–5 การค้นหาอาจใช้เวลาสักครู่ ช่อง **ระบบอ่านภาพ** เริ่มที่ `Auto`; หากกล้อง USB เปิดไม่สำเร็จให้ลอง `DirectShow` หรือ `Media Foundation` ส่วนสตรีมเครือข่ายอาจลอง `FFmpeg` ได้ ความสำเร็จขึ้นกับไดรเวอร์และรูปแบบสตรีมของกล้อง

ช่อง **โมเดล YOLO** ใช้ค่า `yolo11n.pt` ที่ให้มาได้เลย หากเปลี่ยนโมเดล โมเดลนั้นต้องมีคลาส `bottle`, `cup` และ `chair`

## ขั้นตอนทดลอง 8 มุม

1. กด **เชื่อมต่อกล้อง** แล้วรอให้ภาพปรากฏในช่อง **ภาพสดจากกล้อง** และสถานะขึ้นว่าเชื่อมต่อแล้ว
2. กด **เริ่มรอบทดลอง** แล้วรอข้อความพร้อมถ่ายภาพ โปรแกรมจะโหลดและอุ่น YOLO พร้อมเตรียม Deep SORT เบื้องหลัง การเริ่มครั้งแรกอาจใช้เวลาสักครู่ รอบถัดไปจะใช้ YOLO เดิมซ้ำเมื่อไม่ได้เปลี่ยนไฟล์โมเดล ปุ่มถ่ายภาพจะพร้อมเมื่อเตรียมระบบเสร็จ
3. หันกล้องไปมุมที่ 1 รอภาพนิ่ง แล้วกด **ถ่ายภาพมุมที่ 1** โปรแกรมจะบันทึกภาพ ตรวจจับวัตถุ และแสดงภาพพร้อมกรอบในช่อง **ผลตรวจจับล่าสุด**
4. รอให้การประมวลผลมุมปัจจุบันเสร็จและปุ่มถ่ายภาพพร้อมใช้งาน จากนั้นหันกล้องไปมุมถัดไปแล้วกด **ถ่ายภาพมุมที่ …** ทำซ้ำจนครบ 8 มุม ดูจำนวนภาพที่ถ่ายแล้วในแถบความคืบหน้าและภาพตัวอย่างด้านล่าง
5. เมื่อครบ 8 มุม โปรแกรมจะประมวลผลวิธีที่ 2 และเปิดแท็บ **สรุปผล** โดยอัตโนมัติ ระหว่างรอให้ดูสถานะและบันทึกการทำงานด้านขวา
6. กด **เปิดโฟลเดอร์ผล** เพื่อดูภาพและไฟล์ข้อมูลที่บันทึกไว้ หากต้องการทดลองรอบใหม่ ให้กลับแท็บ **ถ่ายภาพ 8 มุม** แล้วกด **เริ่มรอบทดลอง**

หลังถ่ายภาพแล้ว สามารถ **คลิกภาพตัวอย่างมุมที่ต้องการ** ที่แถวล่างของหน้าแรกเพื่อดูภาพพร้อมกรอบของมุมนั้น หากต้องการแทนภาพเดิม ให้หันกล้องไปมุมเดิม รอภาพสดนิ่ง แล้วกด **ถ่ายใหม่มุมที่เลือก** โปรแกรมจะคำนวณผลวิธีที่ 1 ใหม่ทุกภาพเพื่อให้ Object ID ต่อเนื่องกับภาพที่เปลี่ยน ถ้าถ่ายครบ 8 มุมแล้ว โปรแกรมจะคำนวณวิธีที่ 2 และภาพรวมใหม่ด้วย การถ่ายซ้ำหลายครั้งทำให้เวลาของรอบนั้นรวมการทำงานซ้ำ จึงควรเริ่มรอบใหม่ถ้าต้องการเปรียบเทียบเวลาอย่างเป็นธรรม

ปุ่ม **ไปหน้าสรุปผล** เปิดแท็บสรุปได้ทุกเวลา แต่รายละเอียดผลจะครบหลังถ่ายและประมวลผลทั้ง 8 มุมแล้ว หน้าสรุปเลื่อนขึ้นลงได้ด้วยล้อเมาส์หรือแถบเลื่อนด้านขวา และมีปุ่มเลือกการดูผลสองแบบ:

- **ภาพรายมุม:** เลือกมุม 1–8 และเลือก **วิธีที่ 1** หรือ **วิธีที่ 2** เพื่อดูภาพที่วาดกรอบแล้ว พร้อมชนิดวัตถุ ค่าความมั่นใจ พิกัดกรอบ และ Object ID ของภาพนั้น วิธีที่ 2 จะพร้อมหลังถ่ายครบ 8 มุม
- **พาโนรามา / ภาพรวม:** หากต่อภาพสำเร็จ โปรแกรมจะตรวจ YOLO บนภาพพาโนรามาที่ต่อแล้ว วาดกรอบและแสดงรายการวัตถุที่พบ หากต่อไม่สำเร็จจะแสดงภาพตาราง 8 มุมที่มีกรอบจากวิธีที่ 1 พร้อมรายการวัตถุแยกตามมุม

ระหว่างเชื่อมต่อกล้อง โหลดโมเดล และประมวลผล หน้าต่างยังตอบสนองได้ แต่ปุ่มบางปุ่มจะปิดชั่วคราวเพื่อป้องกันคำสั่งซ้อนกัน หากเกิดข้อผิดพลาด ให้อ่านข้อความแจ้งเตือนและสถานะก่อนลองใหม่

## อ่านผลบนหน้าจอ

- **ภาพสดจากกล้อง:** ภาพจากแหล่งภาพที่เชื่อมต่ออยู่ ใช้ตรวจว่ากล้องหันไปทางที่ต้องการก่อนถ่าย
- **ผลตรวจจับล่าสุด:** ภาพจากมุมล่าสุดหลังวิธีที่ 1 ประมวลผล กรอบแสดงตำแหน่งวัตถุ ข้อความบนกรอบแสดงชนิดและ Object ID
- **ภาพรวม 8 มุม:** โปรแกรมพยายามต่อภาพเป็นพาโนรามา หากภาพข้างเคียงซ้อนกันไม่พอ จะใช้ภาพตาราง 8 มุมแทน การต่อภาพไม่สำเร็จไม่ได้หมายความว่าการตรวจจับล้มเหลว
- **จำนวน “ตรวจพบ”:** จำนวนรายการตรวจจับที่นับรวมทุกภาพ วัตถุชิ้นเดิมที่ปรากฏหลายมุมอาจถูกนับหลายครั้ง **ไม่ใช่จำนวนวัตถุจริงที่ไม่ซ้ำ และไม่ใช่ค่าความแม่นยำ**
- **เวลาประมวลผล:** ผลรวมเวลาที่ใช้ตรวจจับและติดตามภาพทั้ง 8 มุมของแต่ละวิธี
- **เวลารวมวิธีที่ 1:** เวลาจริงตั้งแต่กดถ่ายภาพแรกจนประมวลผลภาพที่แปดเสร็จ รวมช่วงที่ผู้ทดลองหันกล้องระหว่างมุม
- **เวลารวมวิธีที่ 2:** **ค่าประมาณ** จากเวลาเก็บภาพชุดเดียวกันโดยหักเวลาประมวลผลวิธีที่ 1 แล้วบวกเวลาประมวลผลวิธีที่ 2 จึงไม่ใช่เวลาที่จับจากการถ่ายรอบที่สองจริง

ตัวอย่าง: หากหน้าสรุปแสดงว่า “ตรวจพบ 12 รายการ” หมายถึง YOLO สร้างกรอบรวม 12 กรอบจากภาพทั้ง 8 มุม อาจเป็นวัตถุเดิมที่ถูกพบหลายครั้ง หรืออาจมีกรอบที่ตรวจผิด ต้องเทียบกับภาพต้นฉบับและข้อมูลเฉลยก่อนสรุปความถูกต้อง โปรแกรม GUI ใช้เกณฑ์ความมั่นใจในการตรวจจับที่ 0.35

ทั้งสองวิธีใช้ภาพและโมเดลเดียวกัน ผลตรวจจับจึงอาจใกล้กัน สิ่งที่เปรียบเทียบได้เด่นชัดคือ **ผลแสดงหลังแต่ละภาพ** กับ **ผลแสดงหลังถ่ายครบ** รวมถึงเวลาในการประมวลผล Deep SORT เริ่มตัวติดตามใหม่สำหรับแต่ละวิธี ดังนั้นเลข ID ระหว่างวิธีที่ 1 กับวิธีที่ 2 ไม่จำเป็นต้องตรงกัน เครื่องหมาย `?` หลัง ID หมายถึงสถานะ `tentative` ซึ่งยังยืนยันการติดตามไม่ได้

## ไฟล์ผลลัพธ์

เมื่อเปิดจาก `.exe` แต่ละรอบจะสร้างโฟลเดอร์ใหม่ที่:

```text
dist\Object360Studio\runs\demo_YYYYMMDD_HHMMSS\
```

| ไฟล์หรือโฟลเดอร์ | ความหมาย |
| --- | --- |
| `raw\` | ภาพต้นฉบับ 8 มุมก่อนวาดกรอบ |
| `online\` | ภาพผลวิธีที่ 1 พร้อมกรอบและ Object ID |
| `batch\` | ภาพผลวิธีที่ 2 พร้อมกรอบและ Object ID |
| `online_detections.csv`, `batch_detections.csv` | รายการที่ YOLO ตรวจพบ: มุม วิธี คลาส ค่าความมั่นใจ และพิกัดกรอบ |
| `online_tracks.csv`, `batch_tracks.csv` | ผล Deep SORT: มุม วิธี คลาส Object ID สถานะ `tentative`/`confirmed` และพิกัดกรอบ |
| `summary.json` | สรุปจำนวนรายการตรวจจับ เวลา แหล่งภาพ และสถานะการต่อพาโนรามา |
| `panorama.jpg` | ภาพที่ต่อเป็นพาโนรามา มีเฉพาะเมื่อต่อสำเร็จ |
| `panorama_detected.jpg` | ภาพพาโนรามาพร้อมกรอบที่ YOLO ตรวจบนภาพที่ต่อแล้ว มีเมื่อการต่อและตรวจสำเร็จ |
| `grid_8_views.jpg` | ภาพตารางจากภาพต้นฉบับ 8 มุม สร้างเสมอ |
| `grid_8_detected.jpg` | ภาพตาราง 8 มุมพร้อมกรอบจากวิธีที่ 1 มีเมื่อต่อพาโนรามาไม่สำเร็จ และใช้แสดงบนหน้าสรุป |
| `overview_8_views.jpg` | ภาพ 8 มุมเรียงเป็นแถวยาว สร้างเสมอ |

ไฟล์ภาพตารางและแถวยาวเป็นการ **นำภาพมาเรียง** ไม่ใช่ภาพ 360 องศาที่ไร้รอยต่อ ส่วนพาโนรามาก็ขึ้นกับส่วนซ้อนกันของภาพและอาจไม่สำเร็จเมื่อหันกล้องต่างมุมมาก

เมื่อรัน GUI จากซอร์ส ผลลัพธ์จะอยู่ในโฟลเดอร์ `runs` ข้างไฟล์ `gui.py` ส่วนเมื่อเปิดจาก .exe ผลลัพธ์จะอยู่ข้างโปรแกรมตามพาธด้านบน

## ข้อควรรู้และแก้ปัญหาเบื้องต้น

- ถ้าเชื่อมต่อกล้องไม่ได้ ให้ตรวจว่ามีโปรแกรมอื่นใช้กล้องอยู่หรือไม่ ลองหมายเลขกล้องอื่น แล้วเปลี่ยน **ระบบอ่านภาพ** ตามชนิดแหล่งภาพ
- ถ้าใช้ URL ผ่าน Wi-Fi ให้ตรวจว่าคอมพิวเตอร์เข้าถึงกล้องได้และ URL เป็นสตรีมหรือภาพ JPEG ตามชนิดที่เลือก
- ถ้าภาพสดไม่ขึ้นหลังเชื่อมต่อ ให้รอภาพจากกล้องก่อนกด **เริ่มรอบทดลอง**; วิดีโอที่สั้นมากอาจหมดก่อนถ่ายครบ 8 ภาพ
- ถ้าต้องการวัดความถูกต้องของการตรวจจับจริง ต้องมีข้อมูลเฉลยที่ทำเครื่องหมายวัตถุไว้ก่อน จำนวน “ตรวจพบ” บนหน้าสรุปเพียงอย่างเดียวบอกความถูกต้องไม่ได้
- Object ID อาจเปลี่ยนเมื่อวัตถุหายจากภาพ ถูกบัง หรือภาพแต่ละมุมต่างกันมาก โปรแกรมไม่ได้รับประกันการรักษา ID รอบทิศทาง

## สำหรับผู้แก้โค้ด

โฟลเดอร์ `.venv` ถูกลบออกเพื่อลดพื้นที่ และ **ไม่จำเป็นต่อการเปิด `.exe`** หากต้องการรันจากซอร์สหรือสร้าง `.exe` ใหม่ ให้สร้างสภาพแวดล้อม Python แล้วติดตั้งแพ็กเกจใหม่:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip install pyinstaller
.\.venv\Scripts\python.exe gui.py
```

หากต้องการสร้าง `.exe` ใหม่ หลังติดตั้งตามขั้นตอนข้างบน ให้รัน `powershell -ExecutionPolicy Bypass -File .\build_exe.ps1` จากโฟลเดอร์นี้


## สิ่งที่เปลี่ยนในเวอร์ชันล่าสุด
- โหลดโมเดล เชื่อมต่อกล้อง และประมวลผลภาพเบื้องหลัง เพื่อให้หน้าต่างยังตอบสนอง
- เริ่มรอบใหม่ใช้โมเดลเดิมซ้ำเมื่อไม่ได้เปลี่ยนไฟล์โมเดล พร้อมอุ่นโมเดลก่อนเริ่มจับเวลา
- แสดงภาพกล้องล่าสุดผ่านบัฟเฟอร์ ลดงานย่อภาพบนหน้าจอ โดยคงภาพต้นฉบับไว้ประมวลผล
- หน้าต่างปรับขนาดเริ่มต้นตามจอ แผงตั้งค่าและความคืบหน้าเลื่อนได้
- เวลาเปรียบเทียบยังเป็นการรันสองวิธีกับภาพชุดเดียวกัน ควรทดลองหลายรอบหลังอุ่นโมเดล

## การทดสอบเวอร์ชันนี้

ทดสอบขั้นตอนถ่ายภาพจำลอง 8 มุมด้วยโมเดลจริง ประมวลผลสองวิธี ถ่ายใหม่ ดูสรุป ใช้โมเดลซ้ำ และอ่านไฟล์วิดีโอผ่านบัฟเฟอร์แล้ว เปิดไฟล์ .exe หลังลบสภาพแวดล้อมสร้างโปรแกรมได้แล้ว การทดสอบนี้ยังไม่ยืนยันความแม่นยำกับวัตถุจริงหรือความเข้ากันได้กับกล้อง USB/Wi-Fi ทุกตัว ดูรายละเอียดใน [VALIDATION.md](VALIDATION.md)
